# 국내 증권사의 미국 산업 In-Depth → 텔레그램

한경 컨센서스·네이버 금융, 하나·미래에셋·토스·교보·유안타·상상인·현대차·한양증권의 공개 목록, 키움·메리츠·NH·신한의 리서치 공개 채널에서 국내 증권사가 발행한 **미국 산업 또는 미국 상장 종목을 주요하게 분석한 산업 심층 리포트**를 선별합니다. 업종과 시가총액 제한은 없습니다. 국내 전용 자료와 미국 종목명이 출처·비교표에만 등장하는 자료는 보내지 않습니다.

매일 한국시간 오후 5시(Asia/Seoul)에 한 번 확인해 PDF 원문 파일을 텔레그램에 첨부합니다. 여러 리포트가 있으면 이 시간대에 파일별로 이어서 보내고, 새 자료가 없으면 전송하지 않습니다. 오후 5시 이후 올라온 자료는 다음 날 확인합니다.

제목 또는 PDF 앞부분의 In-Depth·Deep Dive·인뎁스·심층 표기를 우선 확인합니다. 개별 기업 중심 리포트와 단순 일일·주간 동향은 제외합니다. 표기가 모호한 자료는 검토 대기 또는 선택적 AI 판별로 처리합니다.

미국 관련성은 PDF 앞 200쪽·40만자 이내에서 제목, 산업 주제, 종목명·티커와 본문 분석 문맥으로 판별합니다. 무료 규칙 기반 선별이 기본이며 이름·티커 표기가 불명확한 자료는 누락될 수 있습니다. PDF 원문은 수정 없이 첨부합니다. 로그인 원문 경로는 우회하지 않으며, 공개 파일만 확인된 다른 증권사와 와이즈리포트는 기본 수집 출처에 포함하지 않습니다.

설정, 검증 결과와 운영 상태는 [SETUP_KO.md](./SETUP_KO.md)를 읽어 주세요.

PC 없이 운영하는 기본 배포 방식은 별도의 공개 저장소에서 실행하는 GitHub Actions입니다. [GITHUB_SETUP_KO.md](./GITHUB_SETUP_KO.md)에 공개 저장소·Secrets 등록·최초 초기화 절차와 무료 실행, 예약 실행 지연 조건을 정리했습니다. 토큰과 개인 대화 ID는 저장소 파일에 넣지 않고 Actions Secrets에만 보관합니다.

```bash
npm ci
npm run demo
npm test
npm run typecheck
```

2026-10-26의 31개 증권사 접근 조사에 이어 2026-10-27 GitHub 실행 환경에서 공개 채널 경로를 검증했습니다. 키움·메리츠·NH·신한 4곳을 추가해 기본 수집 출처는 14곳(통합 사이트 2곳, 증권사 경로 12곳)입니다. NH 추가 경로는 제약·바이오 담당 채널이며 모든 NH 리포트를 포함하지 않습니다. 출처별 범위·접속 문제·검증 기록은 [SOURCE_STATUS_KO.md](./SOURCE_STATUS_KO.md)에 정리했습니다. 혼합 목록의 산업·기업 구분, 상세 ID 일치, 페이지 반복·접속 제한, 원문 보존·중복 방지·오후 5시 실행을 검사합니다.

2026-10-27에 전용 공개 저장소 배포와 Actions Secrets 연결을 완료했습니다. GitHub 실행 환경에서 10개 출처의 기존 게시물 961건을 초기 기준점으로 저장하고 상태 브랜치 복원·재저장을 확인했습니다. 초기화 과정에는 전송 없는 공개 PDF 다운로드 검사도 포함합니다. 첫 실제 예약 실행은 2026-10-27 한국시간 오후 5시 예정이며, 초기화 확인은 예약 시각의 실제 발송 성공을 의미하지 않습니다. 추가 4개 출처의 기존 게시물 447건도 발송 없이 기준점에 저장하고 14개 출처 설정을 활성화했습니다. 마지막 사전 PDF 검사는 13곳 성공·한양 1곳 연결 거절로 기록됐으며 기존 이력은 보존했습니다.

```bash
# 목록 2페이지 및 원문 다운로드 검사: 텔레그램 발송 없음
npm run sources:check -- --pdf
```

공개 채널은 공개 게시물에 있는 증권사 원문 서버 링크만 사용합니다. 텔레그램에만 첨부된 파일, 로그인·저장 제한 뷰어는 수집하지 않습니다. 증권사 공식 HTTPS 파일 호스트와 PDF 본문의 발행사 이름을 함께 확인하고 기존 미국 산업·심층 선별과 PDF 중복 방지 규칙을 적용합니다. 공개 채널의 날짜는 발간일 대신 게시일로 표시합니다.

일부 개별 PDF는 시간 초과 등으로 받을 수 없을 수 있습니다. 검증 명령은 실패한 파일도 결과에 기록하며 다른 예시를 확인합니다. 실제 발송 작업에서는 실패한 자료를 재시도 대기로 남깁니다. 교보는 GitHub에서 전체 PDF 다운로드를 확인했습니다. 하나는 같은 GitHub 환경에서도 성공과 연결 종료 오류가 모두 발생해 안정성 문제를 추적 중입니다. 오류를 정상 0건 수집으로 표시하지 않습니다.
